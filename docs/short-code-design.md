# 自定义短码设计

用户可以在单条创建时输入自定义短码，界面会即时预览完整地址。留空时由服务生成。自定义短码匹配 `[a-z][a-z0-9]{2,7}`，并排除 `api`、`page`、`actuator` 和 `error`。批量创建沿用自动生成。

## 唯一性和并发

短码在同一短链域名下唯一，与账号和分组无关。管理接口先校验分组归属，业务服务再校验短码。路由表按完整短链分片，相同地址落在同一张路由分表，由 `full_short_url` 的唯一索引处理冲突。

1. 创建操作获取完整短链对应的 Redisson 跳转锁。
2. 在一个数据库事务中写入 `t_link` 和 `t_link_goto`，并更新布隆过滤器、清除不存在缓存。事务结束后释放锁。
3. 首次访问没有跳转缓存时，在同一把锁下查路由表及短链记录。链接有效时回填 Redis，并返回 HTTP 302。

重复创建时后写者得到「该短码已被占用」。路由写入失败会回滚短链记录，布隆过滤器即使留下误判，跳转仍须由数据库记录确认。批量创建为每条链接开启独立事务，成功的条目继续参与 Excel 导出。

## 停用和恢复

移入回收站会清理跳转缓存并暂停该链接。恢复后仍使用原地址。彻底删除会保留路由和短码占用，防止旧海报、二维码或书签跳到新内容。

## 回归验证

重点验证跨分组抢占短码时只成功一次，以及第二张表写入失败后的回滚。运行方法与结果见[本机验收说明](regression.md)。

查看实现与修复的提交记录可运行 `git log --oneline -- project/src/main/java/io/github/qyl66/linkstamp/project/service/impl/ShortLinkServiceImpl.java`。
